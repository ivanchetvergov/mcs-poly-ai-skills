# common_rules.md — Общие правила пользователя

## Среда разработки
Отчёты формируются в LaTeX в VS Code. Для простого проекта пользователь использует `latexmk main.tex`; если в конкретной работе есть `build.sh` или иная штатная команда, собирай ей. Код на C++ и Python пользователь пишет в VS Code. Java-разработка выполняется в IDE. SQL используется с PostgreSQL в VS Code. На виртуальных машинах выполняются работы с C++, Bash, демонами, скриптами и веб-сервисами; по соответствующему предмету могут требоваться только работы без отчётов.

## LaTeX и структура проекта
Пользователь обычно самостоятельно готовит титульный лист: он уже существует, и обычно нужно менять только фамилии преподавателей, дисциплину, номер и название лабораторной. Не создавай титульник заново, если пользователь не просит об этом.

В отчётах используй пользовательские настройки из `settings.tex`. Типовая структура небольшого проекта:
```latex
% !TEX root = main.tex
\documentclass[a4paper, final]{article}
\input{settings.tex}
\begin{document}
\input{title.tex}
\newpage
\tableofcontents
\newpage
\input{name_file.tex}
\end{document}
```
Для большого отчёта содержимое может быть разделено на несколько файлов `name_file.tex`. Перед подготовкой кода учитывай фактические файлы проекта и не дублируй уже существующие определения, пакеты или настройки из `settings.tex`.

## Ссылки и источники
По возможности в тексте должны быть ссылки на все рисунки, листинги и источники. Для источников используй `\cite{...}` с ключами, существующими в списке использованных источников. Ссылки на рисунки оформляй в формате «(см. рисунок~\ref{fig:...})», для нескольких — «(см. рисунки~\ref{fig:...} и \ref{fig:...})». Для листингов используй аналогичный формат: «(см. листинг~\ref{lst:...})» или «(см. листинги~\ref{lst:...} и \ref{lst:...})». Метки `\label{...}` должны соответствовать ссылкам. Не придумывай несуществующие метки, результаты или источники.

Обычно список использованных источников размещается после заключения. Количество источников уточняется по профилю преподавателя; если задан минимум, соблюдай его. Используй реальные и проверяемые источники, соответствующие теме работы.

## Стиль текста
Пиши просто, точно и по существу. Не используй неестественные фразеологизмы, чрезмерно сложные формулировки и рекламный стиль. Сохраняй терминологию задания и преподавателя. Не меняй заданные пользователем названия разделов. Не добавляй формальные разделы без необходимости.

## Стиль кода
Не добавляй декоративные комментарии наподобие `// --- поля класса ---`. Комментарии оставляй только там, где они действительно помогают понять нетривиальную логику.

В C++/Java и похожем синтаксисе открывающую фигурную скобку ставь сразу после конструкции без пробела перед `{`: например, `for(int i = 0; i < n; i++){`. Сохраняй стиль существующего проекта, если он задан явно.

## Работа с файлами и результатами
Опирайся на фактически предоставленные файлы, код, скриншоты и измерения. Не выдумывай результаты запуска, характеристики оборудования или выводы экспериментов. Если результат необходимо получить на компьютере пользователя, подготовь точные команды и объясни, какие данные прислать для проверки.


## Формат списка источников в LaTeX

Оформляй электронные источники в следующем формате: авторы или организация; название; помета `[Электронный ресурс]`; название сайта или издания; год; URL; дата обращения. Пример записей:

```latex
\renewcommand{\refname}{Список источников}
\addcontentsline{toc}{section}{Список источников}
\begin{thebibliography}{9}

\bibitem{kalamkar}
Kalamkar D., Mudigere D., Mellempudi N., et al. A Study of BFLOAT16 for Deep Learning Training [Электронный ресурс] // arXiv preprint arXiv:1905.12322. -- 2019. -- URL: \url{https://arxiv.org/abs/1905.12322} (дата обращения: 20.09.2026).

\bibitem{google_tpu}
Google Cloud TPU. Improve your model's performance with bfloat16 [Электронный ресурс] // Google Cloud Documentation. -- 2025. -- URL: \url{https://docs.cloud.google.com/tpu/docs/bfloat16} (дата обращения: 20.09.2026).

\bibitem{riscv_bf16}
RISC-V "BF16" Extensions for BFloat16-precision Floating-Point, Version 1.0 [Электронный ресурс] // RISC-V Documentation. -- 2026. -- URL: \url{https://docs.riscv.org/reference/isa/unpriv/bfloat16.html} (дата обращения: 20.09.2026).

\end{thebibliography}
```

Вставляй этот формат как образец библиографических записей и адаптируй его к реальным источникам конкретной работы. Не выдумывай автора, название, год, URL или дату обращения. Чтобы заголовок не дублировался, согласуй `\refname` с текстом в `\addcontentsline`: не добавляй перед `thebibliography` отдельный `\section*`, если окружение само выводит заголовок.
